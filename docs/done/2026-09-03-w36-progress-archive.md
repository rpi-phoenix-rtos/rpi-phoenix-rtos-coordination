- **★★★ AF_UNIX "bytes that were never sent": ROOT CAUSE FOUND, fix implemented (HW test pending).** Not memory corruption at all — **socket ids were recycled**. `unix_bind` publishes a filesystem node whose identity is `{US_PORT, socket id}`; `close()` removes nothing (POSIX-correct — the name lives until `unlink()`, and `unix_unlink` is a no-op stub); but `unixsock_alloc` handed out the **lowest free id**, so a freed id returned at once. `unix_connect`/`send` resolve a pathname to an oid and then `unixsock_get(oid.id)` — which handed them a **different, live socket**, and `send` wrote the payload into *its* buffer. Every observation fits: foreign payload (another pair's traffic, hence absent from the receiver's expected pattern), always at a **chunk boundary** (a whole datagram/write), receiver memory **intact**, and a few-percent rate because it depends on id-recycling order. Linux is immune: a name there resolves to an inode whose socket pointer is cleared on death → `ECONNREFUSED`. **Fix:** allocate ids **monotonically** (wrapping, skipping 0 and live ids, bounded retry), so a stale name never names a live socket again and the caller gets `ECONNREFUSED` — the Linux semantics. **State: implemented but UNCOMMITTED and UNBUILT** in `sources/phoenix-rtos-kernel/posix/unix.c` (net -19 lines: the lowest-gap comparator and the rbtree gap bookkeeping go with it, `lib_rbInit` now passes no augment callback).
