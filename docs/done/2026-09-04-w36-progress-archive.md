## Archived from the weekly log 2026-09-05: #67 root cause + the kernel cache fix

**#67 — SOLVED (2026-09-04).** Torches **7/7 (100%)** after **0/15**; **0 wedges across all 8 boots** (0 corrupt lists, 0 dropped jobs, 0 render timeouts), presents 3,600–3,780. Fix: `dc civac` + `dsb` over a BO's range at create (devices `9bac0f7`, pushed).
- **Cause:** pages handed out for an **uncached** BO still held the **previous owner's dirty cache lines**, evicted later on top of Mesa's uncached writes — corrupting control lists at **64-byte granularity in both directions**. The GPU then executed a half-written list and parked at the first invalid byte: the long-misdiagnosed "wedge". The hardware was never at fault.
- **Why five earlier fixes failed:** every one targeted **BO identity** (handle recycling, address recycling, VA reuse, mappings). The buffer was always correct; its *contents* were being eaten afterwards.

**★★★ THE KERNEL FIX IS LANDED** (kernel `5d8645f6`, §4) and the local winsys workaround is removed, so it is proven to stand alone. Pages mapped uncached must have the previous owner's dirty lines retired first. **Every uncached DMA mapping in the system has this exposure — SD, genet, USB, WiFi** — and the standing history of intermittent, address-dependent, "HW-marginal" faults in those subsystems is exactly what this bug class produces. The winsys `dc civac` is a local patch over a system-wide defect.
