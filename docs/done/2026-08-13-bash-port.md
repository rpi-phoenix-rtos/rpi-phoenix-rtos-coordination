# GNU bash port to Phoenix/RPi4 (owner: "full bash/zsh + coreutils beyond busybox")

Goal: a real bash shell beyond busybox's ash, verifiable over psh/UART (deterministic,
no flaky hardware). Advisor-endorsed as the highest owner-value finishable win.

## Status 2026-08-13: FEASIBLE — configures clean; first blockers root-caused + fixed/identified
bash 5.2.21 (https://ftp.gnu.org/gnu/bash/bash-5.2.21.tar.gz) **cross-CONFIGURES cleanly** against the
aarch64-phoenix toolchain (CC=aarch64-phoenix-gcc, --host=aarch64-phoenix, self-contained sysroot) with a
cross config.cache (below) — all Makefiles + config.h generated. Real programs already port (dropbear/curl/lua/
micropython), so the infra is proven. Compile (`make`) then surfaced two blockers, both tractable:

**Blocker 1 (FIXED at the libphoenix level — the correct fix): `union wait` incomplete type.**
jobs.h:68 `WAIT status;` → posixwait.h:37 selects `typedef union wait WAIT` (undefined on Phoenix) instead of
`typedef int WAIT` **when `_POSIX_VERSION` is not defined**. Phoenix's <unistd.h> did NOT define it (a real gap —
a POSIX system must). FIXED: libphoenix commit **470faee** adds `_POSIX_VERSION`/`_POSIX2_VERSION` = 200809L to
include/unistd.h. No Phoenix core code branches on it → low regression risk. **Needs `--scope core` + boot-verify
to propagate (rebuild libphoenix + sync the header into .toolchain sysroot) before it helps the bash build.**

**Blocker 2 (identified — port-local build flag): mkbuiltins.c K&R errors under gcc 14.**
`too many arguments to function 'xmalloc'; expected 0` etc. — gcc 14 makes implicit-function-declaration + K&R
`()`-as-unprototyped hard errors. mkbuiltins is a HOST build-tool bash compiles + runs during the build. Fix:
build the host tools with permissive flags — `CFLAGS_FOR_BUILD="-Wno-error=implicit-function-declaration
-Wno-error=implicit-int -std=gnu89"` (or patch mkbuiltins prototypes). Port-local, no libphoenix change.
