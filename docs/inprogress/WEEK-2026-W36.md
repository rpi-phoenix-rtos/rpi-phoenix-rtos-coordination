**★★ OWNER RULE (2026-09-03) — ONE BUILD PATH PER PORT; `tools/` IS NOT A PORTS DIRECTORY.** Stated as policy, not a question:
- `tools/` in the coordination repo is **only** for our own tools needed to build the project that cannot easily live anywhere else. "Use `tools/` if no other place makes sense."
- A **normal port** — take a versioned artifact from the internet, apply our patches, build — belongs in `phoenix-rtos-ports` as a framework port. `nano` is the model case.
- Improvements to the system itself belong in `kernel` / `devices` / `libphoenix` / etc.
- The **only** acceptable reason to keep a hand-written script is a build too complex for the framework. Owner expects that to be "very rare and exceptional".
- The problem to eliminate: ports that exist **twice** (framework port *and* legacy `tools/ports/build-*.sh`), where the legacy script is sometimes the one the image actually uses. "We don't need multiple ways to build mv or nano or quake or sdl or python." To be done **carefully, in a controlled, tested way** — one port at a time, not a sweep.
