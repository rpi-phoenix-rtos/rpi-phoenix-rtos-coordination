0. **AF_UNIX: the remaining bug is a ZEROED MEMORY REGION in the forked child — instrumented, waiting for a hit.** ⚠️ **Correction to yesterday's claim: the id fix is NOT the cause of the cross-delivery.** The mismatch reproduced with it in place (`DATA-MISMATCH ... data[]=INTACT`, `recv bytes appear nowhere in data[]`), and the logic never fit: `unix_transfer` uses **`socketpair`**, so no pathname is ever resolved and stale-name/id-reuse cannot apply. - **★★★★★ vkQUAKE TORCHES ROOT-CAUSED AND REPRODUCED ON DEMAND — after five re-diagnoses, it is now a one-line hypothesis with a measured confirmation.** `vkquake +r_lerpmodels 2 +map start` renders the flames: **397–599** and **363–562** lit px across **7/7** frames at the reference viewpoint, against **0 and 0** with the default cvar in the identical scene minutes earlier (quakespasm scores 401–548 for comparison). - **★★★★ ROOT CAUSE OF THE WHOLE TORCH SAGA: `+command` NEVER WORKED ON SHAREWARE DATA — so no Quake I test ever had a controlled viewpoint.** `Cmd_StuffCmds_f()` iterates the **`cmdline` cvar**, and upstream sets that cvar only on the **registered** path, *after* the `gfx/pop.lmp` checksum — the shareware branch `return`s first.
