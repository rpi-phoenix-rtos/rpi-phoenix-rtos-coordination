## 3. IN PROGRESS

**SD card driver — "full speed + correctness"** (the standing `/loop` goal; card is in the Pi)
- ✅ **Your rig works** (NFS root + card as pure raw test device, test tool served from NFS, no card swaps): **write 18.30 MB/s (PIO), read 30.29 MB/s, correctness OK**, at `UHS-I DDR50 1.8V`, root safely on NFS. Repeatable. `tools/sd-scratch-test/`.
- **Root-caused the throughput variance:** a *second* emmc driver instance re-initialises the controller down to `High-Speed 3.3V`, halving throughput (11.86/18.91 vs 18.30/30.29). So: never launch a 2nd instance — and the **DDR50→HS downgrade on re-init is itself a "full speed" lever** worth fixing.
- ⚠️ SDMA-write gate (`sdcard.c:1625`): a gate-ON boot left `/bin/sdtest` on the card unreadable ("not an executable"). Gate **reverted** (safe PIO writes). The write path is structurally correct (the bounce copy-in for writes *is* present), so this looks like the documented controller quirk. Recommend keeping it OFF (D3).
- ⚠️ I bricked one boot adding the emmc line to the nfsroot script (`phfs: bcm2711-emmc - alias is already in use`) — **reverted, boot verified restored**. Now understood: each app's name is a plo *file alias*; the collision only happens when plo comes from the card while the script comes from TFTP. The line itself is fine in a coherent boot.
