## 3d. ★★ ROOT CAUSE LOCALISED — SuperTuxKart's heap corruption is its AUDIO path

The new counter paid for itself on its first gate run, but not the way I expected: it made the
**STK-crash** issue reproducible and then localised it in one A/B.

With the games rebuilt on current libphoenix (so they carry the free-bin guard) and the fault
detector finally able to see the class, STK's gate cycle reported **27 heap-corruption events in a
single run** — `free-bin link is not a plausible chunk`. The signature is not random garbage:

- all 27 chunks **page-aligned**, at an exact **`0xd000` (53248-byte) stride** — an array/pool of
  identically-sized objects;
- the clobbered `next` word is **`0x8003` in 24 of 27** (the outliers `0x7fa3`, `0x8043`);
- `prev == chunk` in 26 of 27.

Those three values read as **16-bit PCM near full scale** (`0x8003` = −32765, `0x7fa3` = +32675), and
53248 bytes is ~302 ms of 16-bit stereo at 44.1 kHz. `next`/`prev` live at `chunk+16`, i.e. **inside
the user payload** — so this is audio sample data written into a block that is on a free bin.

✅ **A/B confirms it: `--no-sound` gives 0 events where the same command gives 27.** And the
no-sound run is not a shorter run that simply had less chance to fail — it went **further**: 59
flipstat samples against 13 (~295 s of presented frames vs ~65 s), same track complexity, and it
reached **lap 2/2** where the sound-on run reached 1/2.

This is very likely the long-standing **STK-crash** row in `docs/KNOWN-ISSUES.md` (~40% of runs, and
two of the four known fault PCs were *inside the allocator*, which the row already read as "the
allocator is the victim"). Audio-driven heap corruption produces exactly that.

⏸ **YOUR CALL, not mine to make silently:** `stk --no-sound` is a one-flag mitigation that removes
the corruption *and* gets further into the race, but it costs the demo its engine sound. I have not
changed the showcase command. The real fix is in STK's audio buffer lifetime (a free while the mixer
still owns the buffer) — app-side, and now cheap to chase since it reproduces every run.
