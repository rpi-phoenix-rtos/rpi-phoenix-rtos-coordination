# Publication-integrity audit — 2026-09-01

Owner's question: *"is there any local, uncommitted or unpushed CODE in the repos
which doesn't get published in github (our org) but DOES affect the build / is
being used in the test? ... no old leftovers, unfinished WIP and stuff like this."*

Answer: **there were three real problems. All three are fixed.** The audit is now
a script — `scripts/publication-audit.sh` — so it is re-runnable, not a one-off
opinion. It exits 0 only when a fresh org clone builds from published sources.

## What the script checks

| | Check | Why it is the dangerous case |
|---|---|---|
| A | commits present locally but never pushed to `publish` | code exists only on this host |
| B | modified tracked files | the local build sees them, a fresh clone does not |
| C | untracked files referenced by tracked source | builds here, fails there |
| C2 | `#include`s resolving to an on-disk but **untracked/gitignored** header | `git status` hides these — the sneakiest class |
| C3 | tracked binary build outputs (*note only*) | over-published bloat, not an integrity risk |
| D | `rootfs-overlay` content that enters images without being tracked | ships in the image, absent from the repo |

Cross-repo and sysroot includes are deliberately ignored: a header resolved from
another published repo or a port's fetched tarball is not this repo's business.

## Findings and fixes

1. **`rootfs-overlay/bin/net-test` (212 KB, unpublished, in EVERY image).**
   `phoenix-rtos-build/build.sh:67` puts `$PROJECT_PATH/rootfs-overlay` first in
   `ROOTFS_OVERLAYS`, so this hand-copied Aug-25 binary was staged into every
   built image while existing in no repo. Its source *is* published
   (`phoenix-rtos-lwip/tests/net-test/`), so the binary was pure leftover →
   **deleted**. Rebuild it from source when the WiFi performance work needs it.
2. **~55 MB of build-output ELFs committed to the coord repo by my own commit
   `e4e266d1b`** (`tools/.gpu-libs/{gl-x11-window,gl-x11-window-daemon,e4-x11-play}`,
   `tools/ttyprobe/ttyprobe`). Root cause: `tools/.gpu-libs/.gitignore` says
   "large generated artifacts, not source" but only matched `*.a`, and these are
   extension-less executables. → **untracked**; the ignore rule now covers the
   whole directory; `tools/ttyprobe/.gitignore` added.
3. **Stale unpublished binaries in sibling trees** (`bt/rpi4-hci/{btctl,rpi4-hci}`)
   → **deleted**. All 16 siblings + coord now report a clean `git status`.

## Left as-is, deliberately

- **13 tracked tool ELFs (~8 MB)** under `tools/` — reported as `bloat`, never a
  finding: they are *over*-published, so they cannot break a fresh clone. Two
  (`ram-stage-play`, `csd-matmul`) are consumed by
  `scripts/make-pristine-nfs-export.sh`, and three of their directories have no
  build recipe at all, so untracking them today would *reduce* reproducibility.
  Proper fix is a build recipe per tool, then untrack — not urgent.
- **~55 MB still in coord git history.** Removing it from HEAD (done) does not
  shrink the history; that needs a force-push of coord `main`. **Owner decision
  (D6)** — flagged, not taken unilaterally.
